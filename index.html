Basic RPG – Unity gyakorlati útmutató

Az útmutató egy egyszerű 3D-s demo alkalmazás elkészítésén keresztül mutatja be a Unity legfontosabb alapfogalmait. A cél nem a Unity teljes körű ismertetése, hanem annak bemutatása, hogyan épül fel egy kisebb játék GameObjectokból, komponensekből, scriptekből, fizikai eseményekből, UI-elemekből és animációból.

1. A demo alkalmazás bemutatása

A tananyag feldolgozása előtt nyisd meg a kész BasicRPG projektet, indítsd el, és először csak figyeld meg a működését. Így a később elkészített objektumok és scriptek nem elszigetelt példák lesznek, hanem már előre látható, hogy milyen szerepet töltenek be a teljes programban.

Kész projekt: A tananyag feldolgozása előtt töltsd le és nyisd meg a kész demo alkalmazást: BasicRPG.zip letöltése.

A játékos egy egyszerű háromdimenziós pályán mozog. A pályán gyémántokat lehet összegyűjteni. A képernyő jelzi az összegyűjtött gyémántokat, és amikor a játékos eléri a szükséges mennyiséget, rövid üzenetet kap arról, hogy az ajtóhoz mehet. Az ajtó csak ekkor nyílik ki. Közben ellenfelek közelednek a játékoshoz, amelyeket a játékos a bottal meg tud támadni.

2. Unity

A Unity egy game engine, vagyis játékmotor. A játékmotor több olyan szolgáltatást biztosít, amelyre játékfejlesztés közben rendszeresen szükség van. Kezeli többek között a háromdimenziós megjelenítést, a fizikai rendszert, a billentyűzet és más beviteli eszközök használatát, a hangot, az animációt és a felhasználói felületet.

A Unityben a program felépítése alapvetően eltér egy hagyományos konzolos programétól. Nem egyetlen forrásfájlból indulunk ki, hanem a jelenetben objektumokat hozunk létre, ezekhez komponenseket rendelünk, majd scriptekkel adjuk meg a viselkedésüket. Egy fal, egy ajtó, egy gyémánt vagy maga a játékos is GameObject.

3. Jelenet és Player objektum

A Unity egy játékpályát vagy képernyőt Scene-nek nevez. Ebben a demóban egyetlen jelenettel dolgozunk. A pálya egyszerű Plane és Cube objektumokból áll. Új 3D objektum létrehozásához kattints jobb gombbal a Hierarchy ablak üres területére, majd válaszd a 3D Object almenüt, azon belül pedig a szükséges típust, például a Plane vagy Cube elemet.

Minden GameObject rendelkezik Transform komponenssel. A Position az objektum helyét, a Rotation az elfordulását, a Scale pedig a méretarányát adja meg. A jelenet szerkesztése során valójában ezeket az értékeket változtatjuk.

4. Scriptek Unityben

A GameObjectok viselkedését C# scriptekkel adjuk meg. A Project ablakban célszerű külön Scripts mappát használni. Nyisd meg ezt a mappát, kattints jobb gombbal az üres területére, majd válaszd a Create → Scripting → MonoBehaviour Script parancsot. Az új script a Project ablakban jelenik meg; itt nevezd át a kívánt névre.

A script fájlneve és az osztály neve legyen azonos. A Player mozgatásához például PlayerMovement nevű scriptet készítünk.

using UnityEngine;

public class PlayerMovement : MonoBehaviour
{
}

Az osztály a MonoBehaviour osztályból öröklődik. Ennek köszönhetően a Unity komponensként tudja kezelni, hozzáadhatjuk egy GameObjecthez, és használhatjuk a Unity által automatikusan meghívott eseménymetódusokat.

A script életciklusa

A Unity nem úgy futtatja a scripteket, hogy egyszer belép egy Main() metódusba és sorban végrehajt mindent. A motor különböző eseményekhez kapcsolódó metódusokat hív meg. Ezek közül a demó szempontjából a következők a legfontosabbak.

MetódusSzerepe
Start()Egyszer fut le, amikor az objektum működése megkezdődik. Kezdeti beállításokra és más komponensek referenciáinak lekérésére használható.
Update()Minden megjelenített képkockában lefut. Billentyűzetkezeléshez és a legtöbb egyszerű játékmeneti művelethez ezt használjuk.
FixedUpdate()A fizikai rendszer rögzített időlépéseihez igazodik. Fizikai erőkkel vagy Rigidbody műveletekkel végzett mozgatásnál ennek van jelentősége.
LateUpdate()Az adott képkocka Update hívásai után fut le. Például követő kamera esetén hasznos, ha a kamera csak a Player mozgása után módosítja a helyzetét.
A MonoBehaviour életciklusának egyszerűsített szemléltetése. A FixedUpdate nem feltétlenül egyszer fut minden renderelt képkockában: lehet, hogy egy képkocka között többször, vagy egyáltalán nem fut le.

Inspectorból állítható mezők

A public mezők megjelennek a script komponens Inspectorában. Ez játékfejlesztésnél különösen praktikus, mert például a mozgás sebességét vagy egy ajtóhoz szükséges gyémántok számát a forráskód módosítása nélkül lehet beállítani.

public float movementSpeed = 5;
public float rotationSpeed = 100;

A script hozzáadásához először jelöld ki a megfelelő GameObjectet a Hierarchy ablakban. Ezután az Inspector alján kattints az Add Component gombra, kezdd el begépelni a script nevét, majd válaszd ki a találatból. Másik lehetőség, hogy a script fájlját a Project ablakból közvetlenül ráhúzod a GameObjectre a Hierarchyban vagy az Inspectorba.

5. Player Movement

A demo a Unity klasszikus Input API-ját használja, ezért új projektben engedélyezni kell, hogy a régi Input Manager is működjön.

A Unity Editor felső menüsorában válaszd az Edit → Project Settings parancsot. A megnyíló Project Settings ablakban fogjuk módosítani a projekt inputbeállítását.
Válaszd a Player részt, majd keresd meg az Other Settings → Configuration csoportot.
Az Active Input Handling értékét állítsd Both-ra. Ha a Unity újraindítást kér, indítsd újra az Editort.

Az Input.GetAxis() -1 és 1 közötti értéket ad vissza. A Vertical tengely az előre-hátra mozgást, a Horizontal a balra-jobbra fordulást vezérli.

using UnityEngine;

public class PlayerMovement : MonoBehaviour
{
    public float movementSpeed = 5;
    public float rotationSpeed = 100;

    void Update()
    {
        float verticalInput = Input.GetAxis("Vertical");
        float horizontalInput = Input.GetAxis("Horizontal");

        transform.Rotate(Vector3.up * rotationSpeed * horizontalInput * Time.deltaTime);
        transform.Translate(Vector3.forward * movementSpeed * verticalInput * Time.deltaTime);
    }
}

A kód elemeinek értelmezése

A két első sorban float típusú lokális változókat hozunk létre. A float lebegőpontos valós szám tárolására szolgál. A verticalInput és horizontalInput változók csak az Update() futása alatt léteznek, ezért nem jelennek meg az Inspectorban.

float verticalInput = Input.GetAxis("Vertical");
float horizontalInput = Input.GetAxis("Horizontal");

Az Input.GetAxis() a Unity Input osztályának metódusa. A zárójelben megadott "Vertical" és "Horizontal" szövegek a Unityben előre definiált inputtengelyek nevei. A metódus egy -1 és 1 közötti valós értéket ad vissza. Ha például a játékos előrefelé mozgató billentyűt nyomja, a Vertical pozitív értéket vesz fel; hátrafelé mozgásnál negatívat.

transform.Rotate(Vector3.up * rotationSpeed * horizontalInput * Time.deltaTime);

A transform az aktuális GameObject Transform komponensére hivatkozik. A Rotate() ezt a Transformot forgatja el. A Vector3.up a háromdimenziós tér pozitív Y irányát jelölő vektor, vagyis ebben az esetben a Player a függőleges tengely körül fordul. A rotationSpeed megadja a forgás sebességét, a horizontalInput az irányt és az input nagyságát, a Time.deltaTime pedig az előző képkocka óta eltelt időt.

transform.Translate(Vector3.forward * movementSpeed * verticalInput * Time.deltaTime);

A Translate() a GameObject helyzetét változtatja meg. A Vector3.forward a GameObject saját előre irányát jelenti. Emiatt a Player nem a világ egy rögzített tengelye mentén mozog, hanem mindig arra halad, amerre előzőleg elfordítottuk. A szorzásban a movementSpeed a sebességet, a verticalInput az előre vagy hátra irányt, a Time.deltaTime pedig az időarányos mozgást biztosítja.

Érdemes megfigyelni: a Vector3.up és Vector3.forward nem számok, hanem háromkomponensű vektorok. Egy vektort valós számmal megszorozva ugyanazt az irányt kapjuk, csak más hosszúsággal. Ezt használjuk fel a mozgás és a forgás mértékének megadására.

A Rotate() a Player függőleges tengely körüli elfordítását végzi. A Translate() a saját előre irányába mozgatja az objektumot, ezért a Player arra halad, amerre éppen néz. A Time.deltaTime az előző képkocka óta eltelt idő; ezzel a mozgás sebessége nem közvetlenül a képkockaszámtól függ.

6. Collision, Trigger és az ajtó

A Unity fizikájában két GameObject közötti kapcsolat alapját a Collider adja. A Collider az objektum ütközési alakját írja le. Egy Cube esetén ez gyakran Box Collider, egy gömbnél Sphere Collider, egy emberhez hasonló alaknál pedig Capsule Collider.

A Collider önmagában még nem mondja meg, hogy az objektum csak érzékeljen egy másikat, vagy valóban fizikailag ütközzön vele. Ezt elsősorban az Is Trigger beállítás és a Rigidbody jelenléte határozza meg.

Fizikai ütközés

Ha azt szeretnénk, hogy két objektum ne tudjon egyszerűen áthaladni egymáson, mindkettőnek Colliderrel kell rendelkeznie, és az érintkező Colliderek Is Trigger beállítása legyen kikapcsolva. A fizikai rendszerben mozgó objektumon rendszerint Rigidbody is található.

Egyszerű példa: a Player egy statikus falnak ütközik.

Ha az ütközéskor kódot is szeretnénk futtatni, akkor nem kell Triggerré alakítani az objektumot. A fizikai ütközés mellett használhatjuk az OnCollisionEnter(), OnCollisionStay() és OnCollisionExit() metódusokat.

private void OnCollisionEnter(Collision collision)
{
    Debug.Log("A Player nekiütközött ennek: " + collision.gameObject.name);
}

A Collision collision paraméter az ütközésről ad információt. A collision.gameObject segítségével elérjük a másik GameObjectet, de a Collision objektumban további adatok is rendelkezésre állnak, például az érintkezési pontok. Vagyis a fizikai ütközés és a kódfuttatás nem zárja ki egymást.

Fontos: 3D-ben a normál OnCollision... eseményekhez legalább az egyik érintett Colliderhez nem kinematikus Rigidbody szükséges. Ha mindkét oldal csak statikus Collider, vagy mindkét Rigidbody kinematikus, a fizikai callbackek nem ugyanúgy viselkednek. A tananyagban ezért a mozgó Player beállításait mindig tudatosan kell kialakítani.

Trigger esemény

Ha azt szeretnénk, hogy a két objektum ne állítsa meg egymást, hanem az átfedéskor csak kód fusson le, az egyik Collideren be kell kapcsolni az Is Trigger lehetőséget. Mindkét GameObjectnek rendelkeznie kell Colliderrel, és legalább az egyik oldalon Rigidbody vagy más fizikai body szükséges ahhoz, hogy a Unity trigger eseményt generáljon.

Trigger esetén legalább az egyik érintkező Collider Is Trigger beállítása aktív. *A másik Collider lehet normál Collider; a lényeg, hogy az egyik fél trigger legyen.
private void OnTriggerEnter(Collider other)
{
    Debug.Log("Belépett a triggerbe: " + other.gameObject.name);
}

Itt a paraméter típusa már nem Collision, hanem Collider. Az other annak a Collidernek a referenciája, amely belépett a triggerbe. Ha csak a belépés pillanatára van szükségünk, OnTriggerEnter()-t használunk. A OnTriggerStay() addig fut a fizikai frissítések során, amíg az átfedés fennáll, az OnTriggerExit() pedig a kilépéskor hívódik meg.

Hogyan lehet ugyanazzal a Playerrel falnak ütközni és gyémántot érzékelni?

Nem kell választani a két működés között. Egy GameObject-hierarchiában több Collider is lehet, és ezek különböző feladatokat láthatnak el. Ez történik a BasicRPG Player objektumánál is.

Objektum / komponensBeállításFeladat
Player gyökérobjektumRigidbodyA Player részt vesz a fizikai rendszerben.
Player gyökérobjektumCapsule Collider, Is Trigger bekapcsolvaGyémánt, Enemy és más érzékelési területek felismerése.
Body / Head / Arm gyermekobjektumoknormál Colliderek, Is Trigger kikapcsolvaA Player fizikai alakja; ezekkel ütközhet például a falnak.
Falnormál Collider, Is Trigger kikapcsolvaFizikai akadály.
DiamondCollider, Is Trigger bekapcsolvaÁthaladáskor trigger eseményt okoz, de nem állítja meg a Playert.

Így ugyanaz a Player kétféle kapcsolatban is részt vehet. A fal a Player normál Colliderével találkozik, ezért fizikai ütközés történik. A Diamond a Player triggerterületével kerül átfedésbe, ezért OnTriggerEnter() fut le. A két viselkedés nem ütközik egymással, mert külön Colliderek szolgálják a két célt.

Általános szabály: ha valaminek fizikailag meg kell állítania a Playert, használj normál Collidert. Ha csak észlelni szeretnéd, hogy a Player belépett egy területre, használj Trigger Collidert. Ha mindkettőre szükség van, használhatsz több Collidert ugyanazon GameObject-hierarchiában.

Fotocellás ajtó

Az ajtónál most az érzékelés a fontos, ezért a Door objektum Box Collidere Triggerként működik. Jelöld ki a Door objektumot a Hierarchyban. Az Inspectorban az Add Component gombbal adj hozzá Box Collider komponenst, majd kapcsold be az Is Trigger jelölőt. A Collider méretét úgy állítsd be, hogy a Player az ajtóhoz közeledve belépjen ebbe a térbe.

A belépéskor a Unity meghívja az OnTriggerEnter() metódust. Az if feltétel ellenőrzi, hogy a belépő GameObject neve valóban "Player"-e. Az összehasonlításhoz a == operátort használjuk.

private void OnTriggerEnter(Collider other)
{
    if (other.gameObject.name == "Player")
        directionY = 1;
}

A directionY egy egész típusú állapotváltozó. Az 1 azt jelenti, hogy az ajtó felfelé mozogjon. Kilépéskor -1 értéket adunk neki, ami lefelé irányt jelent.

private void OnTriggerExit(Collider other)
{
    directionY = -1;
}

Az ajtó tényleges mozgatását az Update() végzi. Az if és else if elágazások több feltételt vizsgálnak: az ajtónak megfelelő irányba kell mozognia, de közben nem lépheti túl a minY és maxY értékekkel megadott határokat.

void Update()
{
    if (directionY == 1 && transform.position.y < maxY)
        transform.Translate(Vector3.up * speed * Time.deltaTime);
    else if (directionY == -1 && transform.position.y > minY)
        transform.Translate(Vector3.down * speed * Time.deltaTime);
    else
        directionY = 0;
}

A && logikai ÉS operátor: az elágazás törzse csak akkor fut le, ha mindkét feltétel igaz. A transform.position.y a Door aktuális Y koordinátáját adja meg. A Vector3.up és Vector3.down a felfelé, illetve lefelé mutató irányvektorok.

7. Gyémántok és gyűjtés

A projektben a gyémánt nem külső modellből származik. Egy Diamond gyökérobjektum alatt két Cube található, amelyeket eltérő irányban elforgatva egyszerű gyémántszerű forma jön létre. Ez jól mutatja, hogy egy látványosabb játékelem elkészítéséhez nem feltétlenül van szükség kész 3D modellre.

A Diamond prefab szemléltető felépítése a feltöltött projekt alapján.

A Diamond gyökérobjektumot jelöld ki a Hierarchyban. Az Inspectorban az Add Component gombbal adj hozzá Sphere Collider komponenst, majd kapcsold be az Is Trigger lehetőséget. A kész prefabban a Collider sugara 0,9. Ezután az Inspector tetején a Tag mezőnél hozz létre Diamond taget, és rendeld hozzá az objektumhoz.

Lebegés és forgás

A gyémánt folyamatosan forog, közben pedig fel-le mozog. A forgás egyszerű: minden képkockában kis mértékben elforgatjuk a függőleges tengely körül. A lebegésnél a moveUp változó tárolja, hogy a gyémánt éppen felfelé vagy lefelé haladjon, a minY és maxY pedig a két szélső helyzetet.

void Update()
{
    transform.Rotate(Vector3.up * rotationSpeed * Time.deltaTime);

    if (moveUp && transform.position.y < maxY)
        transform.Translate(Vector3.up * movementSpeed * Time.deltaTime * (Mathf.Sin(time) + 1));
    else if (!moveUp && transform.position.y > minY)
        transform.Translate(Vector3.down * movementSpeed * Time.deltaTime * (Mathf.Sin(time) + 1));
    else
        moveUp = !moveUp;

    time += Time.deltaTime;
}

A Mathf.Sin(time) értéke időben folyamatosan változik, ezért a mozgási sebesség sem teljesen állandó. A gyémánt így nem egyszerűen azonos sebességgel jár fel-le, hanem a mozgása valamivel természetesebb hatású.

Gyűjtés és Prefab

A kész Diamond objektumot húzd a Project ablak egy Prefabs mappájába. A Prefab újra felhasználható sablon: több példányt lehet a jelenetbe helyezni úgy, hogy mindegyik ugyanabból az alapbeállításból származik.

A gyűjtést a Playeren lévő PlayerCollector komponens végzi. Amikor a Player trigger Collidere átfedi a Diamond trigger Colliderét, lefut az OnTriggerEnter(). A script a tag alapján ellenőrzi, hogy valóban gyémántról van-e szó.

private void OnTriggerEnter(Collider other)
{
    if (other.gameObject.tag == "Diamond")
    {
        nrOfDiamondsCollected++;
        textNrOfDiamondsCollected.text += "*";
        Destroy(other.gameObject);
    }
}

Ha a belépő objektum Diamond taggel rendelkezik, növeljük a számlálót, frissítjük a felületet, majd a Destroy() eltávolítja az adott gyémántpéldányt a jelenetből.

8. UI és a feltételes ajtó

A gyémántok számát nem a 3D jelenetben, hanem a képernyőre rajzolt felhasználói felületen jelenítjük meg. A Unity ilyen elemeit egy Canvas nevű GameObject alá kell szervezni. A Canvas tekinthető annak a kétdimenziós felületnek, amelyre a szövegek, gombok és más UI-elemek kerülnek.

Canvas létrehozása

A Hierarchy ablakban kattints jobb gombbal egy üres területre, majd válaszd a UI → Canvas elemet. A Hierarchyban megjelenik egy Canvas GameObject. A Unity általában egy EventSystem objektumot is létrehoz; ez az egérrel, billentyűzettel vagy más beviteli eszközzel kezelhető UI-elemek eseményeihez szükséges.

A Canvas Inspectorában a Render Mode határozza meg, hogyan jelenjen meg a felület. Ennél a demónál a Screen Space - Overlay a legegyszerűbb választás: a UI közvetlenül a játék képe fölött jelenik meg, és nem kell külön kamerához vagy 3D pozícióhoz kötni.

A Canvas a teljes képernyőre illeszkedik. A rajta lévő szövegek helyét nem 3D koordinátákkal, hanem Rect Transform és anchor beállításokkal adjuk meg.

TextMeshPro szövegelem létrehozása

Jelöld ki a Canvas objektumot a Hierarchyban, majd kattints rajta jobb gombbal. A megjelenő helyi menüben válaszd a UI → Text - TextMeshPro elemet. Az új TextMeshPro GameObject a Canvas gyermekeként jön létre. Ha a Unity ekkor felajánlja a TextMeshPro alap erőforrásainak importálását, válaszd az alap TMP resources importálását.

Ha még nincs Canvas a jelenetben, UI-elem létrehozásakor a Unity képes automatikusan létrehozni egyet. A tananyagban azonban szándékosan előbb hozzuk létre a Canvast, mert így egyértelműbb, hogy a szövegek ennek a gyermekobjektumai.

Rect Transform és pozicionálás

A hagyományos 3D GameObjectok Transform komponense helyett a UI-elemek Rect Transform komponenst használnak. Ez nemcsak pozíciót, elfordulást és méretarányt tárol, hanem egy téglalap méretét és a szülőhöz viszonyított igazítását is.

Jelöld ki a létrehozott TextMeshPro GameObjectet a Hierarchyban. Az Inspector tetején a Rect Transform komponens jelenik meg. Itt állítható többek között a szélesség, magasság, az X/Y pozíció és az Anchor. Az Anchor azt mondja meg, hogy a szöveg a Canvas mely pontjához vagy területéhez legyen kötve. Ha például a gyémántszámlálót a bal felső sarokhoz horgonyozzuk, különböző képernyőméretek mellett is ehhez a sarokhoz igazodik.

A Rect Transform pozíciója mindig az Anchor beállításához viszonyítva értelmezhető. Ezért célszerű előbb a horgonyzást, és csak utána a pontos pozíciót beállítani.

A gyémántszámlálónál célszerű először a Rect Transform Anchor Presets gombjával a bal felső sarokhoz igazítást választani, majd az X és Y értékekkel néhány pixel távolságot hagyni a képernyő szélétől. A Width és Height a szöveg számára fenntartott téglalap méretét adja meg.

A TextMeshPro komponensben állítható maga a szöveg, a betűméret, a betűstílus és az igazítás. Ennél a demónál nincs szükség bonyolult formázásra; a lényeg, hogy a felirat jól olvasható legyen a játék háttere előtt.

Canvas Scaler

A Canvas GameObjecton található Canvas Scaler komponens segít abban, hogy a felület különböző felbontásokon is használható maradjon. Egyszerű demónál is célszerű a UI Scale Mode értékét Scale With Screen Size-ra állítani, majd megadni egy referenciafelbontást. Ekkor a Unity a teljes UI-t ehhez viszonyítva méretezi.

Ehhez jelöld ki a Canvas objektumot a Hierarchyban, majd az Inspectorban keresd meg a Canvas Scaler komponenst. A UI Scale Mode legördülő mezőben válaszd a Scale With Screen Size lehetőséget. Oktatási példában megfelelő kiindulás lehet például az 1920 × 1080 referenciafelbontás.

A gyémántszámláló összekapcsolása a scripttel

A PlayerCollector scriptben a textNrOfDiamondsCollected mező típusa TextMeshProUGUI. Ez egy referencia lesz a Hierarchyban létrehozott TextMeshPro komponensre.

public TextMeshProUGUI textNrOfDiamondsCollected;

A TextMeshProUGUI egy osztálytípus: nem magát a kiírt szöveget tároljuk benne, hanem annak a UI-komponensnek a referenciáját, amelynek a tartalmát módosítani szeretnénk. Mivel a mező public, a PlayerCollector komponens Inspectorában megjelenik egy üres referenciahely.

A Hierarchyban jelöld ki a Player objektumot.
Az Inspectorban keresd meg a PlayerCollector komponenst és benne a Text Nr Of Diamonds Collected mezőt.
A Hierarchyból húzd rá erre a mezőre a Canvas alatt található gyémántszámláló TextMeshPro GameObjectet.

Ezután a script a referencia text tulajdonságán keresztül módosíthatja a képernyőn megjelenő feliratot.

textNrOfDiamondsCollected.text += "*";

A .text a TextMeshPro komponens szövegtartalmát jelenti. A += operátor nem lecseréli a meglévő értéket, hanem hozzáfűzi az új szöveget. A projektben minden összegyűjtött gyémánt után egy új * karakter kerül a felirathoz.

A „Go to door” üzenet

A második szövegelem létrehozásához ismét jelöld ki a Canvas objektumot a Hierarchyban, kattints rajta jobb gombbal, majd válaszd a UI → Text - TextMeshPro elemet. Nevezd át például Text (Go to door)-ra. Ezt a feliratot célszerű a képernyő alsó-középső területére helyezni, ezért a Rect Transform Anchor Presets között válassz alsó-középső horgonyzást, majd állítsd be a kívánt Y távolságot.

A felirat alaphelyzetben ne legyen látható. Jelöld ki a GameObjectet a Hierarchyban, és az Inspector tetején kapcsold ki a GameObject neve melletti aktív jelölőt. A script később a SetActive(true) hívással ideiglenesen bekapcsolja.

if (playerCollector.nrOfDiamondsCollected == minNrOfDiamondsToOpen)
    textGoToDoor.gameObject.SetActive(true);

if (playerCollector.nrOfDiamondsCollected >= minNrOfDiamondsToOpen)
    elapsedTimeOfTextGoToDoor += Time.deltaTime;

if (elapsedTimeOfTextGoToDoor >= 2)
    textGoToDoor.gameObject.SetActive(false);

Az első if pontos egyenlőséget vizsgál: az üzenet akkor jelenik meg, amikor a játékos éppen eléri a szükséges darabszámot. A második feltétel ettől kezdve növeli az eltelt időt. Amikor ez eléri a két másodpercet, a harmadik feltétel ismét kikapcsolja a szöveg GameObjectjét.

Az ajtó nyitási feltétele

Az ajtónak tudnia kell, hány gyémántot gyűjtött a Player. A DoorMovement scriptben ezért egy GameObject referencia mutat a Playerre.

public GameObject player;
PlayerCollector playerCollector;

void Start()
{
    playerCollector = player.GetComponent<PlayerCollector>();
}

A player egy GameObject típusú referencia. A hozzárendelést az Editorban végezzük el: a Hierarchyban jelöld ki a Door objektumot, az Inspectorban keresd meg a DoorMovement komponenst, majd a Hierarchyból húzd a Player GameObjectet a komponens Player mezőjére.

A GetComponent<PlayerCollector>() a megadott GameObjecthez kapcsolt komponensek között keres egy PlayerCollector típusút, és annak referenciáját adja vissza. Így az ajtó közvetlenül hozzáfér a gyémántok aktuális számához.

private void OnTriggerEnter(Collider other)
{
    if (other.gameObject.name == "Player")
    {
        if (playerCollector.nrOfDiamondsCollected >= minNrOfDiamondsToOpen)
            directionY = 1;
    }
}

A >= operátor jelentése „nagyobb vagy egyenlő”. Az ajtó tehát akkor is nyitható marad, ha a játékos a minimálisan szükségesnél több gyémántot gyűjtött össze. A minNrOfDiamondsToOpen public mező, ezért az értéke a DoorMovement komponens Inspectorában állítható; a kész projektben ez az érték 3.

9. Enemy és támadás

Az Enemy szintén egyszerű primitive objektumokból összeállított Prefab. A gyökérobjektum Enemy taggel rendelkezik, rajta található az EnemyHealth és az EnemyFollowsPlayer script, valamint egy nagyobb Box Collider, amelynél az Is Trigger be van kapcsolva.

Az EnemyFollowsPlayer a Start() során megkeresi a Player nevű objektumot. Az Update() minden képkockában kiszámítja a Player irányát, fokozatosan felé fordítja az Enemy-t, majd a pozícióját is a Player felé mozdítja.

void Start()
{
    player = GameObject.Find("Player");
}

void Update()
{
    if (player == null) return;

    Vector3 direction = player.transform.position - transform.position;
    Quaternion targetRotation = Quaternion.LookRotation(direction);

    transform.rotation = Quaternion.Slerp(
        transform.rotation, targetRotation, rotationSpeed * Time.deltaTime);

    transform.position = Vector3.MoveTowards(
        transform.position, player.transform.position, speed * Time.deltaTime);
}

A Quaternion.LookRotation() előállítja azt az elfordulást, amely a Player irányába néz. A Quaternion.Slerp() nem azonnal állítja erre az irányra az Enemy-t, hanem fokozatos fordulást hoz létre. A Vector3.MoveTowards() hasonló módon közelíti a pozíciót.

Támadás

A kész projektben a PlayerAttack script a Player gyökérobjektumon található. Ugyanitt van a nagyobb, triggerként működő Capsule Collider is. A támadás tehát nem a Stick saját Collideréből indul ki: a Player triggerterülete érzékeli, hogy egy Enemy a közelben van.

Az Enemy gyökérobjektumán szintén trigger Box Collider található. Amíg az Enemy és a Player triggerterülete átfedi egymást, a Unity meghívja az OnTriggerStay() metódust. Ha ekkor a játékos lenyomja a Space billentyűt, a script ellenőrzi az Enemy taget, majd lekéri az EnemyHealth komponenst.

private void OnTriggerStay(Collider other)
{
    if (Input.GetKeyDown(KeyCode.Space))
    {
        if (other.gameObject.tag == "Enemy")
        {
            EnemyHealth enemyHealth = other.gameObject.GetComponent<EnemyHealth>();
            enemyHealth.Injure(damage);
        }
    }
}

Az EnemyHealth egyszerű egész számmal tárolja az életerőt. Az Injure() levonja a kapott sebzést. Ha az érték nullára vagy az alá csökken, az Enemy objektumot a SetActive(false) kikapcsolja. Az objektum tehát nem törlődik a jelenetből, csak inaktívvá válik.

10. Animáció

A támadáshoz most adjuk hozzá a botot a Playerhez. Hozz létre egy egyszerű Stick objektumot, például egy keskeny Cube-ból, és helyezd a Player egyik karja mellé. Ha közvetlenül a Stick saját középpontja körül forgatnánk, a mozgás nem úgy viselkedne, mintha a játékos a bot végét fogná.

Sok 3D-s alkalmazásban, például a Blenderben, külön megadható vagy áthelyezhető egy objektum forgatási középpontja. Ebben a Unity-demóban egyszerűbb megoldást használunk: létrehozunk egy üres StickPivot GameObjectet ott, ahol a forgás középpontját szeretnénk, majd a Sticket ennek gyermekévé tesszük. Ezután nem a Sticket, hanem a StickPivotot forgatjuk. A gyermekobjektum követi a szülő Transformját, ezért a bot a kívánt pont körül lendül el.

Player ├── Body ├── Head ├── Arm1 ├── Arm2 ├── Main Camera └── StickPivot └── Stick
A StickPivot egy külön szülőobjektummal helyettesíti a forgási középpont közvetlen áthelyezését.

A Unityben az animációt érdemes két külön fogalomra bontani. Az Animation ablakban magát a mozgást készítjük el: megadjuk, hogy egy objektum valamely tulajdonsága hogyan változzon az idő függvényében. Az Animator ablak ezzel szemben azt szabályozza, hogy az elkészült animációk közül éppen melyik fusson, és milyen feltételekkel lehessen egyik állapotból a másikba váltani.

Animation – transzformációk változása az idő függvényében

Egy egyszerű animáció felfogható úgy, mint időben egymás után végrehajtott Transform-változások sorozata. Nem kell minden egyes képkockához külön megadnunk a pontos pozíciót vagy elfordulást. Néhány fontos időpillanatban kulcsértékeket, úgynevezett keyframe-eket adunk meg, a Unity pedig kiszámítja a köztes értékeket.

A projektben a StickPivot objektumot animáljuk, nem közvetlenül a Stick geometriáját. Ez azért praktikus, mert a Stick a Pivot gyermekobjektuma. Ha a Pivot elfordul vagy elmozdul, a bot automatikusan követi. A forgás középpontját így a StickPivot helyzete határozza meg.

A feltöltött StickAnimation clip fő kulcsértékei. A Unity a megadott időpontok közötti értékeket interpolálja.

A feltöltött projekt StickAnimation clipje egy másodperc hosszú és 60 mintavétel/másodperc beállítást használ. A clip a StickPivot Transformjának több tulajdonságát is módosítja. A legfontosabb kulcsértékek:

IdőRotation XPosition YScale
0 s0°1,82(1, 1, 1)
0,33 s45°1,29kb. (2,02; 1,93; 2,11)
0,58 sköztes értékköztes értékvissza (1, 1, 1)-re
1 s0°1,82(1, 1, 1)

Ez a clip tehát nem egyszerűen elforgatja a botot. A Pivot helyzetét és méretét is megváltoztatja, majd visszaállítja az eredeti állapotot. Oktatási szempontból ez jól szemlélteti, hogy az Animation ablakban nem csak Rotation, hanem Position, Scale vagy más animálható komponensérték is változtatható.

Az animáció elkészítése az Animation ablakban

A Hierarchyban jelöld ki a StickPivot objektumot.
A Unity Editor felső menüsorában válaszd a Window → Animation → Animation parancsot. A megnyíló Animation ablak mindig a Hierarchyban kijelölt animálható GameObjecthoz kapcsolódik.
Hozz létre egy új Animation Clipet StickAnimation néven, vagy válaszd ki a már létrehozott clipet.
Az Add Property gombbal add hozzá a Transform azon tulajdonságait, amelyeket változtatni szeretnél. A projektben a Position, Rotation és Scale is szerepel.
Állítsd az időmutatót 0 másodpercre, és rögzítsd a kiinduló Transform-értékeket. Ez lesz az első keyframe.
Állítsd az időmutatót körülbelül 0,33 másodpercre, majd módosítsd a StickPivot Transformját. A projektben ekkor az X tengely körüli elfordulás 45°, a Y pozíció lejjebb kerül és a Scale is megnő.
0,58 másodpercnél a Scale visszaáll az eredeti értékre, 1 másodpercnél pedig a Position és Rotation is visszatér a kezdő állapotba.

Amikor az Animation ablakban a piros Record mód aktív, a Unity a kijelölt időpontban végzett Transform-módosításokból automatikusan keyframe-et hozhat létre. Fontos ezért figyelni arra, hogy melyik időpontra áll az időmutató, amikor egy értéket módosítunk.

Animation és script: ugyanazt a mozgást természetesen C# kódból is végre lehetne hajtani. Az Animation Clip előnye, hogy a mozgás időbeli lefolyása vizuálisan szerkeszthető, és a Unity végzi a köztes Transform-értékek kiszámítását.

Animator – az animáció állapotainak vezérlése

Az Animator nem magukat a keyframe-eket szerkeszti. Egy állapotgépet ad, amely megmondja, hogy melyik Animation Clip fusson, és milyen feltételekkel történjen váltás az állapotok között.

A projektben két állapot található. Az alapállapot neve Empty State; ebben nem fut animáció. A másik állapot a StickAnimation. Az Animator Controllerben szerepel egy TriggerHit nevű Trigger paraméter.

A feltöltött StickPivot Animator Controller egyszerű állapotgépe.

A Any State → StickAnimation átmenet feltétele a TriggerHit. Ez azt jelenti, hogy bármely aktuális állapotból elindulhat a támadó animáció, ha ez a trigger aktiválódik. A StickAnimation → Empty State átmenetnél nincs külön feltétel, viszont aktív a Has Exit Time. Így a clip lefutása után az Animator automatikusan visszatér az alapállapotba.

Az Animator beállítása

A Project ablakban kattints jobb gombbal egy üres területre, és válaszd a Create → Animator Controller parancsot. Nevezd el például StickPivot Animator Controller-nek. Ha a mellékelt projektet vizsgálod, ezt a controller fájlt már készen megtalálod.
Jelöld ki az Animator Controller fájlt a Project ablakban, majd a Unity Editor felső menüsorában válaszd a Window → Animation → Animator parancsot. Az Animator ablakban ennek a controllernek az állapotgépe jelenik meg.
Az alapállapot legyen egy üres Empty State. Ez azt jelenti, hogy normál helyzetben nem fut a bot animációja.
Húzd be a StickAnimation clipet az Animator ablakba. Ezzel létrejön a hozzá tartozó állapot.
A Parameters panelen hozz létre Trigger típusú paramétert TriggerHit néven.
Készíts átmenetet az Any State állapotból a StickAnimation állapotba, és Conditionként add meg a TriggerHit paramétert.
Készíts visszavezető átmenetet a StickAnimation állapotból az Empty State-be, és hagyd aktívan a Has Exit Time beállítást.

Végül a StickPivot GameObjecthez Animator komponens és a StickAnimator script tartozik. A script a Start() metódusban lekéri az Animator komponenst. Amikor a játékos lenyomja a Space billentyűt, a script aktiválja a TriggerHit paramétert.

Animator animator;

void Start()
{
    animator = GetComponent<Animator>();
}

void Update()
{
    if (Input.GetKeyDown(KeyCode.Space))
        animator.SetTrigger("TriggerHit");
}

Ezzel jól elkülönülnek az egyes feladatok. A PlayerAttack script a játékmeneti hatást végzi, vagyis sebzi a közeli Enemy-t. A StickAnimator ugyanarra a Space billentyűre csak a vizuális animációt indítja el. Az Animation Clip leírja a StickPivot Transformjának időbeli változását, az Animator Controller pedig azt szabályozza, mikor fusson ez a clip.

Összefoglalva: a támadásnál ugyanaz a bemenet két egymástól különálló rendszert indít el. A PlayerAttack a játék szabályait kezeli, a StickAnimator pedig a megjelenítést. Ez később is fontos szemlélet: a játék logikáját és a vizuális visszajelzést érdemes külön kezelni.
